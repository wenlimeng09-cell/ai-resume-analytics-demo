# AI 简历优化助手的数据分析与效果评估项目方案（历史设计稿）

**实施范围**　当前原型从输入简历和岗位描述走到报告导出。看板使用固定合成样本，已实现任务漏斗、模拟模板对比和分群分析。下文保留早期对投递、面试和留存的研究设计，这些项目尚待独立采集数据、实现和验证。

## 一、项目定位

早期方案从数据分析和产品运营视角，提出了一个需要长期验证的问题。

> AI 简历优化助手是否有效提升了用户的求职效率？

本次作品集统计生成建议后至少采纳一条并导出报告的任务比例。

## 二、业务背景

求职用户在投递岗位时，经常面临以下问题：

- 简历与 JD 匹配度不足；
- 不知道如何针对不同岗位调整简历；
- 修改简历耗时较长；
- 投递后反馈率低；
- AI 给出的建议可能泛泛而谈，用户未必愿意采纳。

现有原型支持输入简历、解析 JD、生成修改建议和导出报告。后续投递与面试反馈属于早期设计中的延伸场景。

## 三、用户路径

下列路径为早期设想。当前原型在第 6 步后可导出报告，第 7、8 步属于后续研究。

1. 进入产品
2. 上传简历
3. 输入 JD
4. 从岗位描述识别关键词
5. 基于规则生成修改建议
6. 用户采纳建议
7. 用户完成投递
8. 用户获得面试反馈

## 四、核心分析问题

早期问题清单如下。当前数据可描述路径流失和组间差异。投递与面试结果、真实用户的行为变化仍待验证。

1. 用户是否顺利完成核心使用路径？
2. 哪个环节流失最严重？
3. AI 建议是否提升了用户投递完成率？
4. 不同用户群体的使用效果是否存在差异？
5. 不同 Prompt 模板是否影响建议采纳率？
6. AI 建议质量是否影响用户后续投递和面试反馈？
7. 产品下一步应该优先优化哪里？

## 五、核心指标体系

### 1. 早期用户漏斗设想

现行看板按同一任务内的事件顺序构建六步漏斗。以下按用户计数的投递漏斗保留作后续研究设计，两种分母不可混用。

| 漏斗环节 | 指标名称 | 计算方式 |
|---|---|---|
| 进入产品 | 访问用户数 | 进入产品页的去重用户数 |
| 上传简历 | 简历上传率 | 上传简历用户数 / 访问用户数 |
| 上传 JD | JD 上传率 | 上传 JD 用户数 / 上传简历用户数 |
| 生成建议 | 建议生成率 | 生成建议用户数 / 上传 JD 用户数 |
| 采纳建议 | 建议采纳率 | 采纳建议用户数 / 生成建议用户数 |
| 完成投递 | 投递完成率 | 完成投递用户数 / 采纳建议用户数 |
| 获得面试 | 面试反馈率 | 获得面试用户数 / 完成投递用户数 |

### 2. 留存指标设想

| 指标 | 含义 |
|---|---|
| 次日留存率 | 用户首次使用后第 2 天是否再次使用 |
| 7 日留存率 | 用户首次使用后第 7 天是否再次使用 |
| 周活跃用户数 | 7 天内至少使用一次产品的用户数 |
| 人均优化次数 | 用户平均生成简历优化建议的次数 |

### 3. 分群指标设想

可以按用户类型拆分：

- 应届生；
- 实习生；
- 转行用户；
- 有 1-3 年经验用户；
- 有 3 年以上经验用户。

重点比较：

- 各群体建议采纳率；
- 各群体投递完成率；
- 各群体面试反馈率；
- 各群体留存率。

### 4. 后续真实 A/B 实验指标设想

实验目标：验证不同 Prompt 模板是否能提升 AI 建议采纳率。

| 实验组 | Prompt 特征 | 观察指标 |
|---|---|---|
| A 组 | 通用建议型 Prompt | 建议采纳率、投递完成率 |
| B 组 | JD 匹配型 Prompt | 建议采纳率、投递完成率 |

核心指标：

- 建议采纳率；
- 投递完成率；
- 人均采纳建议数；
- 面试反馈率。

### 5. 建议质量指标设想

可以为每条 AI 建议打标签或评分：

| 质量维度 | 评分说明 |
|---|---|
| 具体性 | 建议是否具体到简历某一段、某一技能或某一项目 |
| JD 匹配度 | 建议是否对应 JD 中的岗位要求 |
| 可执行性 | 用户是否可以直接根据建议修改 |
| 表达质量 | 建议是否清晰、专业、没有空话 |
| 采纳结果 | 用户是否实际采纳该建议 |

可设计 1-5 分评分，并分析质量分与采纳率、投递率、面试反馈率之间的关系。

## 八、当前样本的分析结果

1. 同一任务到达六步的数量依次为 1,250、1,086、888、794、774、371。采纳后有 403 个任务没有导出，环节流失率为 52.1%。
2. 794 个已生成建议的任务中，371 个完成采纳和报告导出，有效优化任务完成率为 46.7%。
3. A 组建议采纳率为 60.5%（1,092 / 1,806），B 组为 77.6%（1,406 / 1,812）。脚本按任务分配模板并预设组间概率差异，真实模板效果仍待验证。
4. 待处理建议数在当前固定样本中全部为零。要分析未处理建议与报告导出的关系，需采集存在不同待处理数量的任务。

## 九、产品优化建议

以下是设计方向。建议展示与逐条采纳已可体验，复制、部分采纳、专项反馈等方向是否值得投入仍需验证。

### 1. 优化 AI 建议展示

将 AI 建议从泛泛描述改为“问题定位 + 修改建议 + 示例改写”三段式结构。

### 2. 增加 JD 匹配解释

在每条建议旁展示它对应的 JD 原文关键词，增强用户信任。

### 3. 降低采纳门槛

提供“一键应用建议”“部分采纳”“复制改写文案”等操作。

### 4. 针对转行用户提供专属路径

增加“可迁移能力识别”“经历重写模板”“目标岗位差距分析”等功能。

### 5. 建立建议质量反馈机制

允许用户对建议点击“有用 / 无用”，并用反馈数据持续优化 Prompt。

## 十、简历写法

搭建基于规则的简历优化原型和产品分析看板，以 8,007 条模拟事件还原从访问至报告导出的任务路径，定位采纳后未导出的 403 个任务，提出采纳后导出引导的验证方案。分组对比按任务分配 A、B 模板，分别计算建议级采纳率和任务级导出率。

## 十一、面试讲述结构

面试时可以按这个顺序讲：

1. 我为什么选择这个项目；
2. 产品的核心用户路径是什么；
3. 我设计了哪些数据表和核心指标；
4. 我用漏斗分析发现了哪个关键问题；
5. 我如何用分群和模拟模板对比提出待验证的问题；
6. 我如何评估 AI 建议质量；
7. 我最终给出了哪些产品优化建议；
8. 如果真实上线，我会如何继续迭代。
