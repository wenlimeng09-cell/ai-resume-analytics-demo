# AI 简历助手的用户转化分析

本项目用一个可交互的简历优化原型，研究求职者从输入简历到导出修改报告的路径。看板使用固定模拟数据，工作台使用关键词规则和填写模板。所有反馈记录也由脚本生成。

[打开 Streamlit 演示](https://ai-resume-analytics-demo-pziwa7ezziinjsbc5dpqtb.streamlit.app/)

## 从哪一步开始看

| 页面 | 可以回答的问题 |
| --- | --- |
| 转化总览 | 哪一步流失最多？可以按求职身份筛选，查看每一步到达的任务数、用户数以及环节分母。 |
| 模板与人群 | 两组模板的建议采纳率、任务导出率各是多少？差异能否由模拟规则解释？ |
| 简历工作台 | 岗位要求在简历中有哪些原文依据？可以粘贴文本、导入 TXT 或 Markdown、采纳或拒绝建议、导出报告。 |
| 数据口径 | 各表一行代表什么？每个指标如何计算？哪些问题需要真实数据？ |

## 固定样本给出的发现

900 名模拟用户产生 8,007 条事件。一次优化任务由同一用户针对一个岗位发起，每个任务在每一步最多计一次。按时间顺序还原的任务漏斗如下。

| 访问 | 输入简历 | 输入 JD | 生成建议 | 至少采纳一条 | 导出报告 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,250 | 1,086 | 888 | 794 | 774 | 371 |

- **采纳后未导出是最大的环节流失。** 已采纳的 774 个任务中有 403 个未导出，流失率为 52.1%。可以据此测试采纳后的导出引导，现有日志只能定位流失环节。
- **有效完成率是 46.7%。** 分子是既采纳又导出的 371 个任务，分母是已生成建议的 794 个任务。该模拟样本只允许已采纳任务导出，因此有效完成率与报告导出率相同。
- **两组的采纳率相差 17.1 个百分点。** A 组采纳 1,092 / 1,806 条建议，B 组采纳 1,406 / 1,812 条。模板按任务分配，同一用户可参与两组。模拟器预设 B 组优势，差值及按用户聚类计算的区间用于演示分组分析。
- **待处理建议对导出的影响仍是未知。** 固定样本中所有任务的待处理建议数都为 0。建议生成充当曝光代理，数据没有记录每条建议是否实际进入用户视野。

## 数据与实现

| 文件或目录 | 用途 |
| --- | --- |
| `app.py` | 页面导航、筛选、漏斗、模板与人群对照 |
| `resume_workspace.py` | 简历输入、任务管理、建议处理和会话内报告下载 |
| `logic/metrics.py` | 有序漏斗、任务及建议指标、聚类区间 |
| `logic/resume_analyzer.py` | 岗位词库、原文匹配、规则模板和报告组装 |
| `data/*.csv` | 固定演示快照，包括用户、行为事件、生成任务、建议和模拟反馈 |
| `data/generate_mock_data.py` | 生成一份使用当前规则的模拟样本及 SQLite 副本 |
| `outputs/` | 项目说明、早期方案、简历描述、面试讲述稿 |
| `tests/` | 指标与规则回归测试 |

覆盖率的分母是规则能够识别的岗位要求类别数，分子是简历原文中提及的类别数。它只能反映文本覆盖。采纳只更新处理状态，修改简历后重新生成才会更新覆盖率。工作台输入与报告仅用于该次 Streamlit 会话，下载会把 Markdown 文件交给当前用户。

## 本地运行

在项目根目录执行以下命令。推荐 Python 3.12。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

回归检查使用 `python -m unittest discover -s tests -v`。固定样本已经随仓库提供，启动时可直接使用。若需试验生成逻辑，可运行 `python data/generate_mock_data.py`，默认写入 `work/generated-data/`。输出使用当前规则，可能与已发布快照的数量不同。
